# 实现设计

## 技术选择

首版已采用 Java 21、Spring Boot、H2和原生网页，实现领域服务及受限查询。个人演示不需要额外数据库或前端构建工具。生产演进可迁移到MySQL和独立前端，但不能把计划能力称为已经实现。

文档解析、嵌入模型和检索引擎需通过真实PDF、表格及扫描件样本选型。BeModel 的文本解析和混合检索实现可作代码阅读参考，不能直接视为已经满足OCR、结构保留和大规模检索要求。

## 业务模型

| 概念 | 关键属性 / 关系 |
|---|---|
| 设备 | 编号、型号、位置、配置版本；包含部件 |
| 部件 | 编号、类型、适用型号；可能关联故障现象 |
| 故障现象 | 编号、同义词、描述；可能原因 |
| 故障原因 | 编号、描述；证实该原因所需证据 |
| 维修动作 | 编号、适用范围、来源；针对原因 |
| 维修案例 | 设备、现象、已确认原因、实际动作、结果、时间、审核状态 |
| 技术资料 | 文档ID、版本、适用型号、章节/页码、有效状态 |

“可能原因”与“案例中已确认原因”分别保存。历史案例不能证明当前设备原因相同。合成案例不填未经验证的操作规程。

## 数据映射

source_mapping 保存来源系统、表、字段、目标概念属性、值字典、映射版本。首轮使用仓库内CSV导入测试数据库，不连接客户生产库。后续只读适配台账与工单数据，使用明确的表和字段白名单。

## 查询和智能体

1. 解析提问中的设备、型号和现象；设备不明确时追问。
2. 用确定性查询读取设备档案及已审核维修案例。
3. 根据型号、配置和资料有效状态过滤文档，再检索相关章节。
4. 模型整理证据、提出追问与有来源的建议。
5. 返回事实、可能原因、待确认事项与引用，记录工具执行过程。

首轮工具：get_device、search_approved_cases、retrieve_documents、get_case_evidence。限制执行次数、工具权限和单次结果量。工具故障、资料不足时说明原因，不能将模型生成文本充当查询结果。

不开放模型执行任意SQL。先用固定参数查询；扩展语义问数时，另行实现只读连接、白名单、行数限制、超时和校验。

## 页面

- 维修工作台：提问、追问、答案、引用、工具记录。
- 设备与案例：档案、历史记录、已确认原因。
- 知识管理：资料版本、适用范围、发布状态。
- 反馈审核：待审核、通过、驳回、审核者和版本记录。

## 反馈治理

反馈先存草稿，原始内容保留。审核时检查设备关联、真实结果、资料引用和敏感内容。审核发布后才可被正式检索；停用后不可用于新回答，但历史答案仍可追溯原版本。

## NATS扩展

由独立适配层接现有平台，实际主题与字段按客户协议确认。需要event_id去重、关联ID、持久化处理状态、失败重试和错误记录；平台内部消息队列不等于业务协议已接通。

## 资源验证

尚未做容量测算。记录资料总页数、分块数、扫描件比例、模型版本、请求并发、解析耗时、检索耗时、生成耗时和总耗时，再确定部署资源。50台PLC并不直接等于50个模型并发请求。
