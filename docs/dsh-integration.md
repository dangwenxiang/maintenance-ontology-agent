# v0.2 DSH 接入与验收

日期：2026-10-13。

## 架构

工作台→Java API→DSH Runtime Host→DSH Agent Loop→只读工具→Java设备/维修/知识服务。

Java的AgentService现在负责业务依据与运行服务边界；原Java模型网关及手写JSON工具循环已移除。运行服务使用官方DSH包装配插件。NATS接入暂未实现。

## 首轮已实现

- 同步兼容问答，以及异步任务提交、事件游标查询和取消。
- 设备绑定的DSH会话列表、继续提问、重启后恢复。
- DSH原生调度get_device、search_cases、search_documents。
- 模型协议适配与合成演示模型；演示模式在界面明确标注。
- 内部HTTP凭证、工具参数Schema、当前设备与身份范围检查。
- 记录执行事件、原始业务依据及引用；已完成问答可提交维修反馈。
- 反馈审核流程保持原有逻辑，未审核记录不会成为正式查询依据。

## 启动与数据

python3 scripts/dev.py会构建必要的Java程序、安装缺失的Node依赖，生成临时内部凭证，启动两个本机服务。Ctrl+C停止整套服务，数据仍保留。

Java业务数据在data/；DSH日志与宿主状态在runtime/data/。首版只能单机单运行服务，不能让两个Host同时使用同一数据目录。

默认端口8087与8117。端口已占用时使用--port和--runtime-port，脚本不会自动结束其他程序。

ADMIN_TOKEN仍需自行设置，审核及资料发布默认关闭。当前没有企业SSO或完整用户角色，不能当作企业身份平台完成交付。

## 验证方法

- Java行为测试：设备/型号范围、资料版本、审核状态、内部工具凭证、身份与设备范围、原始证据不可被轮询覆盖。
- Node测试：真实官方DSH循环、工具调度、事件日志、继续会话、恢复、取消后再执行、执行轮数限制、模型HTTP协议转换。
- 整套HTTP烟测：Java与Node通过内部接口调用真实业务数据；反馈提交及审核；重启Node后继续原会话并看到新审核案例；取消任务。
- 页面已加入DSH模式、会话选择、查询过程、引用和反馈入口；浏览器工具访问被安全策略拦截，实际页面交互尚未验证。

模型测试中的外部服务为本机模拟接口；没有验证真实模型效果、客户资料质量或生产容量。
